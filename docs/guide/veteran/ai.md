# AI 使用教程

![可疑进程，尝试终止](/images/veteran-ai.jpeg)

你大概已经用过豆包：写作文、翻译、问"这道题怎么做"，它答得都挺好。

但你如果只用它聊天，等于请了个很聪明的顾问，却让他站在门外隔门喊话——他看不见你的项目、碰不到你的文件，更不能替你跑一遍试试。这篇文章讲的就是把那扇门打开：**Agent**（让它动手）和 **Skill**（把你的经验写成它每次都读的说明书）。

两样都用顺了，你干活的效率会和只会往对话框里贴代码的同学拉开一个身位。

## 一、先认清：AI 有三种用法，只有一种能替你动手

| 用法 | 例子 | 它能看到的 | 适合干什么 |
| --- | --- | --- | --- |
| 网页/App 聊天 | 豆包、DeepSeek、Kimi | 只有你粘贴过去的那几段 | 问概念、解释报错、出题考你 |
| 编辑器里的补全 | Copilot、通义灵码 | 你正在写的那几十行 | 补重复代码、补函数名 |
| **Agent（智能体）** | Qoder、Trae、Claude Code，以及上面那些工具的 Agent 模式 | **你的整个项目**，并能改文件、跑命令 | 从"我要一个功能"到"它真的跑起来了" |

Agent 和聊天 AI 的本质区别是两件事：**上下文**和**动手能力**。

聊天框里的它，不知道你的目录结构、你装了什么库、你的代码写到哪一行。你粘两百行过去，它也只能靠猜。Agent 直接接在你的代码目录上：自己翻文件、自己搜函数，改完自己编译，挂了看着报错接着改。**这个"改 → 跑 → 看报错 → 再改"的循环，才是它真正省时间的地方。**

所以选工具的原则就一条：**能读你整个项目、并且能执行命令。** 只会在侧边栏里回你话的，那是聊天框搬进了编辑器，不算 agent。

## 二、Agent：把它当成手很快、但没上过你课的新人

想象队里新来了个人：打字飞快，什么库都见过，就是完全不知道你们在干什么。带他的办法是——需求说清楚、验收讲明白、关键的地方自己看一眼。对 agent 一模一样。

### 1. 需求四件套

```text
目标：让程序读一段视频，把画面里的红色装甲板灯条框出来
输入输出：输入是视频文件路径，输出是画了框的图 + 终端打印灯条中心坐标
约束：C++ + OpenCV4，不要引入新依赖，代码放 src/ 下；这一步只做识别，不做解算
验收：你自己跑一遍，把结果图和终端输出贴给我；我另外再拿两段视频复测
```

四行分别解决：**做什么 / 吃什么吐什么 / 不许乱来 / 怎么算过关**。

对比一下大多数人第一次会说的话："帮我写个装甲板识别程序"。这句话它也能给你一份代码，但你大概率会拿到一个跑不起来、或者跟你想要的完全不是一回事的东西，然后你们俩开始互相折磨。

一次典型的来回长这样：你说四件套 → 它读代码、写实现、编译、报错、自己修 → 给你结果和一句"我改了什么" → 你看 diff、跑一遍、提出下一个不满意的点。

### 2. 说法对比

| 别这么说 | 这么说 |
| --- | --- |
| 帮我写个识别装甲板的程序 | 上面那四件套 |
| 报错了，你看下 | 把报错**原文**整段贴进去，别只说"编译报错了" |
| 不对，重写 | 具体说哪不对：框偏了 / 漏检了 / 帧率掉到 10 了 |
| 帮我优化下 | 现在 15 fps，目标 30 fps，帮我先定位瓶颈 |

你给的信息越全面，它给的答案越像样。**"它不行"的多数情况，其实是"你没说清楚"。**

### 3. 什么时候该插手

**它开始自由发挥**：改了你没让它改的文件、加了一堆不需要的抽象（"为了方便扩展，我引入了 xxx"）——立刻叫停让它回退。

为什么？因为 AI 生成的代码最后还是要人工复审一遍的，你最后写的代码自己都看不懂，那我要你干什么，我要的是代码又不是屎山。

### 4. 把上下文喂饱

Agent 能力的上限，一半取决于你喂了什么：

- **报错贴全文**，从第一行贴到最后一行，别自己总结；
- **让它先读再写**："先读一遍 src/ 下的代码，讲清楚现在的结构，再动手"；
- **把资料丢进去**：规则手册 PDF、队里的旧代码、相机参数、数据集说明；
- 项目里放一份 README 写清楚"这是什么、怎么编译、怎么跑"，它每次都能自己学会。

## 三、Skill：别再每次重新解释一遍

你可能会想：那我每开一个新对话，都得把这套规矩重说一遍？

**Skill 就是解决这个的。**

上学老师会给你发书，按照书上的做你就可以考高分。Skill 就是**写给 AI 的同款文档**，而且它每次干活前都会认真读完，不会嫌长。

你可以把任意一本书（比如我们这个知识库）做成 skill，有什么不会的让 AI 通过这本书的知识教你。

比如说了解机甲规则，也可以用 skill，让 AI 帮你总结。

## 四、AI 使用指南

1. 使用 AI 不要有心理负担。如果你有感觉的话，这篇文章和[《如何使用 Linux》](/guide/veteran/linux)都是用 AI 写的，这个网站也是 AI 写的。该用就用。
2. 使用 AI 的前提是你会。人制造汽车就是为了省下走路的力气，我不是让你从青岛到济南全程都得走不能坐车，但是你不能只会坐车不会走路。所有 AI 写出的代码，不管你是谁，都要自己看一遍！都要自己看一遍！都要自己看一遍！
